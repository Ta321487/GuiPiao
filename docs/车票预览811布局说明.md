# 车票预览窗口 · 811 布局说明

本文说明 **`TicketPreviewWindow`**（车票预览 / 票面参数调整）里 **811×509 票面布局** 相关概念与代码位置，便于对照改功能。更偏「行程预览、只读表单」的说明见同目录 **`车票预览功能要点.md`**。

**边界（先分清两件事）：**

- **业务数据**：行程、**`TripItem`**、票种标志、支付渠道、Hint、身份、编码文本等。左侧表单与票面「写什么字」都来自这里（经 **`TicketPreviewDraft`** 包装）；与数据库是否写回无关，但**性质上仍是业务侧数据**。
- **模板布局（本说明主体）**：**`ObservableTicketFaceLayout`** + **`ticket-face-layout.json`**。只描述 **811 上各块放哪、多大、用什么字体族**；工作台里拖拽、对齐网格、**复制/粘贴字号**、导出/载入 JSON，**动的都是模板**，不替代业务录入。

同一张窗口里两种东西叠在一起，容易混读；下文凡提「布局」「811」「工作台」，均指 **模板**，不是「改票种规则」或「改支付业务含义」。

---

## 1. 同窗口、两种模式

| 模式 | 枚举 | 典型入口 | 左侧 | 右侧 811 票面 |
|------|------|----------|------|----------------|
| **票面参数调整（布局工作台）** | `LayoutWorkbench` | 设置里打开 | 显示 **811×509 版面参数**（滑块、编辑元素、字体、JSON 等） | 仍可预览票样 |
| **车票预览** | `UserTripPreview` | 行程列表「预览」等 | **车票信息多为只读**；不显示布局工作台 | 按当前布局 + 行程数据渲染 |

- 判定：`TicketPreviewViewModel.SessionMode` → `IsLayoutWorkbench`、`IsTripFieldsReadOnly`、`WindowTitle` 等。
- 代码：`Model/TicketPreviewSessionMode.cs`，`View/TicketPreviewWindow.xaml`，`ViewModel/TicketPreviewViewModel.cs`。

---

## 2. 811×509 是什么

- 右侧 `Canvas` 固定 **宽 811、高 509**（单位与设备无关像素）；缩放通过 **`Grid.LayoutTransform` + `ScaleTransform`**（绑定 `ScaleX` / `ScaleY`）实现，**不用**外层 `Viewbox`（避免与窗口内缩放百分比逻辑叠加混乱；见 `TicketPreviewWindow.xaml` 内注释）。
- 票面上每个可见块（票号、检票、站名、日期段、二维码等）各自有 **Canvas.Left / Top** 与 **字号**（部分还有 **字体族**），存在 **`ObservableTicketFaceLayout`** 里。
- **蓝票 / 红票** 各一套布局：`_layoutBlue`、`_layoutRed`。当前用哪套由 **`IsRedTicket`** 决定，绑定用 **`ActiveLayout`**（只读属性，指向其中一套）。

---

## 3. 数据从哪来（别混在一起）

| 层次 | 作用 |
|------|------|
| **`TicketPreviewDraft`** | 左侧「车票信息」、票面文字内容（站名、车次、检票口字符串等）。包装 `TripItem`，带计算属性（如字距站名、箭头微调）。 |
| **`ObservableTicketFaceLayout`** | **纯几何与字体参数**（坐标、字号、可选字体族），**不含**业务文案。蓝/红各一份。 |
| **`LayoutDefaultFontFamily`**（ViewModel 上） | 全局后备字体字符串（WPF `FontFamily.Source` 风格）；各块自己的 `*FontFamily` 可空，空则回退到这里。 |

**一句话**：左侧与 **`Source.*`** 绑定的是 **业务文案**；**`ActiveLayout.*`** 与 JSON 是 **版式模板**。预览窗口里顶多是在用业务数据**喂**模板，看效果、调几何；不是把业务规则搬进布局文件。

票面 XAML 里：文字内容多绑 **`SelectedDraft` / `Source.*`**；位置字号多绑 **`DataContext.ActiveLayout.*`**（经 `RelativeSource` 指到窗口的 ViewModel）。

---

## 4. 布局 JSON（持久化）

- **默认路径**：程序目录下 `Config/ticket-face-layout.json`（`TicketFaceLayoutJson.GetDefaultFilePath()`）。
- **结构**：`TicketFaceLayoutFileDto` —— `defaultFontFamily`、`workbenchSelectedElement`（上次工作台选中的「编辑元素」枚举名）、**`blue` / `red`** 各一份 `TicketFaceLayoutSideDto`。
- **读写**：`Model/TicketFaceLayoutJson.cs`。载入后 `ApplyTo(ObservableTicketFaceLayout)`，并会跑 **`EnsureStationZhanFromLegacyIfUnset`**、**`EnsureCheckInValueFromLegacyIfUnset`** 等，给旧文件补全拆分后的字段。
- **关闭工作台窗口**：会尝试 **静默写回** 默认 JSON（`TryPersistLayoutOnWorkbenchClosing`）。

---

## 5.「编辑元素」下拉（`TicketFaceLayoutElementKind`）

工作台左侧选 **哪一块** 在编，就驱动 **`SelectedLayoutElementItem`** → **`LayoutIsolationTargetKind`**（给 XAML 里 **高亮/隔离** 哪一块用）以及 **滑块绑定的 `EditorAnchorX/Y` 等**。

常见拆分（避免一行里两件事绑同一套坐标）：

- **出发站 / 到达站**：站名主体、「站」字、拼音 **分开**；站名左右字号用 **`DepartStationNameFont` / `ArriveStationNameFont`**，与共享的 `StationNameFont`（兼容/导出）并存。
- **检票**：**`CheckInLabel`**（「检票：」）与 **`CheckInValue`**（检票口内容）**坐标与字号独立**；旧 JSON 只有旧检票锚点时由 **`EnsureCheckInValueFromLegacyIfUnset`** 把内容块默认摆到标签右侧。

完整列表以代码为准：`ViewModel/TicketPreviewViewModel.LayoutEditor.cs` 里 **`LayoutElementItems`** + `Model/TicketFaceLayoutElementKind.cs`。

### 与左侧「车票信息」能不能对上一行？

**能对上的是「同一张票上的同一份业务数据」**：右侧票面文字仍绑 **`SelectedDraft` / `Source.*`**，左侧改车次、站名、日期、票种等，票面上该出现的地方都会变；你选「编辑元素」调的是**这一块字在 811 上的几何**，不是另一套业务字典。

**但不是「表单一行 ↔ 下拉一项」**：下拉按 **票面绘制块** 拆得很细（例如「出发日期」在左侧是一个框，在布局里是 **年份数字、「年」字、月份数字……「开」字** 等多项；检票口是 **标签** 与 **内容** 两项；发/到站各 **站名主体 / 「站」字 / 拼音** 三项）。所以项数会比左侧多，属正常。

**左侧有、下拉里没有对应项的（当前实现）**：**附加信息**——左侧表单可编辑并写入 **`TripItem`**，但 **`TicketPreviewWindow.xaml` 的 811 票面 Canvas 里并未绘制该段文案**，因此 **`LayoutElementItems`** 与 **`TicketFaceLayoutElementKind`** 里也没有对应块；不是下拉漏了，而是版式模板里还没有「附加信息」这一块。若将来要在报销凭证上印出该字，需要新增票面控件 + 布局 JSON 字段 + 枚举项后，才会出现在「编辑元素」里。

**改签类型** 与 **车票用途** 一样：811 票面有独立 **`TextBlock`**，枚举 **`TicketFaceLayoutElementKind.TicketModificationType`**，布局字段 **`TicketModificationTypeLeft` / `Top` / `Font` / `FontFamily`**（JSON 与 **`TicketFaceLayoutPatch`** 键名与之对应）；载入旧布局文件时若缺省，由 **`EnsureTicketModificationTypeFromPurposeIfUnset`** 在「车票用途」锚点上方写入默认几何。

**下拉有、左侧没有对应输入框的**：**箭头**（纯版式）；**底部报销说明**（多由票号等拼出来的展示行，不是单独业务字段）。

## 6. 工作台左侧控件在干什么（极简）

- **全局后备字体**：整票默认字体；下拉选系统字体或「浏览」选字体文件（解析成可保存的 `Source` 字符串）。
- **本元素专用字体（可空）**：只对当前「编辑元素」生效；空 = 跟全局后备一致。
- **X / Y / 字号 / 额外尺寸**：写入 **`ActiveLayout`** 上对应字段；**`PushEditorToLayout`** 把滑块值写回布局对象。
- **在票面上拖拽微调**（勾选「在票面上拖拽微调位置」）：透明 **`LayoutEditOverlay`** 上 **`BeginWorkbenchSurfaceDrag`** / **`ApplyWorkbenchSurfaceDrag`**（见 `TicketPreviewWindow.xaml.cs`），内部再更新 **`ActiveLayout`** 对应锚点；滑块编辑仍走 **`PushEditorToLayout`**。历史上另有 **`ApplyLayoutDrag`**（增量 dx/dy），以当前 `LayoutEditor` 与窗口事件实际调用为准。
- **复制/粘贴字号**（811 各逻辑块的字号 / 箭头线粗 / 二维码边长）：见下文 **§7**。
- **导出/载入 JSON、恢复内置默认**：操作 `TicketFaceLayoutFileDto` 与两套 `ObservableTicketFaceLayout`。

---

## 7. 工作台「复制字号 / 粘贴字号」（811 几何格式刷）

与左侧行程**业务文案**无关，**只读写模板里的字号/线粗/边长**；针对 **`TicketFaceLayoutElementKind`** 里每个可在工作台选中的块，**「复制字号」应总能缓存当前块的主尺寸，「粘贴字号」应总能按目标块类型写入并夹紧**，不能出现「有的块能复制、二维码却不能」这类不一致。

### 7.1 行为约定（`TicketPreviewViewModel.LayoutEditor.cs`）

- **命令**：**`CopyWorkbenchFontSizeCommand`**、**`PasteWorkbenchFontSizeCommand`**；缓存 **`CopiedWorkbenchFontSize`**（`double?`，语义随源块类型变化）。
- **复制取值**：除 **二维码** 外，均复制 **`EditorFontSize`**（正文为字号，箭头为线粗）；**二维码** 复制 **`EditorExtra`**（与 UI 上「二维码边长」滑块一致，**不是**被隐藏的 `EditorFontSize` 影子值）。
- **粘贴写回**：按当前 **`SelectedLayoutElementItem.Kind`** 解释——**二维码** 将缓存写入 **`EditorExtra`**（边长约 40～400）；**箭头** 写入 **`EditorFontSize`**（线粗约 0.5～4）；**其余** 写入 **`EditorFontSize`**（字号约 6～72）。允许跨块粘贴（例如从票号复制到二维码，数值会按目标允许范围夹紧）。
- **可用性**：**`CanCopyWorkbenchFontSize`** = 已选编辑元素；**`CanPasteWorkbenchFontSize`** = 已有缓存且已选目标元素（**不**再要求 `EditorShowsFontSize`，避免二维码块无法参与格式刷）。说明文案 **`WorkbenchCopiedFontSizeCaption`**。
- **界面**：**`TicketPreviewWindow.xaml`** 中「票面参数调整」折叠区内的「复制字号」「粘贴字号」按钮（复制按钮带 **`CanCopyWorkbenchFontSize`**）。

## 8. XAML 里「工作台隔离」是什么意思

- 预览/工作台 **都希望看到整张票**；选中某一元素时，用 **`TicketLayoutIsolationToVisibilityConverter`** + **`LayoutIsolationTargetKind`** 控制：非当前编辑块是否 **淡化/隐藏**（具体规则以转换器与 XAML `ConverterParameter` 为准，参数为枚举名如 `DepartStation`、`CheckInLabel`）。
- 字体显示：**`LayoutFontFamilyMultiConverter`** 按绑定顺序取 **第一个非空的字体字符串** 转成 `FontFamily`（块专用 → 全局后备等）。

## 10. 改布局时容易晕的点（对照用）

1. **改的是「字在哪」还是「写什么字」**：坐标/字号在 **`ActiveLayout`**；站名、检票口文字在 **`TripItem` / `TicketPreviewDraft`**。  
2. **蓝票改了红票没变**：两套 `_layoutBlue` / `_layoutRed`，记得切 **蓝/红** 或各保存一份 JSON。  
3. **枚举名与 JSON `workbenchSelectedElement`**：保存的是枚举字符串；旧值 **`CheckIn`** 会映射为 **`CheckInLabel`** 恢复工作台。  
4. **旧 JSON 缺新字段**：依赖各 **`Ensure*FromLegacyIfUnset`**，不必手算所有新坐标。  
5. **工作台「复制字号」与二维码**：二维码块不显示字号滑块（**`EditorShowsFontSize`** 为 false），但复制时应取 **边长**；若新增 **`TicketFaceLayoutElementKind`** 分支，记得在 **`PullEditorFromLayout` / `PushEditorToLayout`** 与 **`GetWorkbenchCopiedSizeValue` / `ApplyWorkbenchPastedSizeValue`** 中保持一致，否则格式刷会漏写或写错字段。  
6. **「在票面上拖拽微调」点选某块**：`TicketPreviewWindow.xaml.cs` 里 **`LayoutWorkbenchHit.TryResolveKind`** 沿命中视觉的父链查找 **`LayoutWorkbenchHit.Kind`**。若某块（如票种简字 `Grid`、支付 `ItemsControl`、二维码 `Image`）根节点未设置 **`hit:LayoutWorkbenchHit.Kind`**，则无法同步左侧「编辑元素」下拉。
