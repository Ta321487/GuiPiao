# GuiPiao 手机端（MAUI）设计与能力规划

> **强制原则：设计语言必须与现有 PC（WPF）对齐。**  
> 交互可因触屏/单栏重做，**视觉身份不可另起炉灶**。若与本文或 `docs/工程规范.md` 冲突，以更新更近且经确认的决策为准。  
> 同步协议见 `docs/功能规划-多端同步OCR与火车迷.md` 与 PC 端 `SyncHttpServer` API。

---

## 1. 定位

| 项 | 约定 |
|----|------|
| 形态 | .NET MAUI 客户端（优先 Android；Windows 目标便于本机预览） |
| 角色 | **采集与随身查看**；PC SQLite 仍为权威 |
| 产品名 | 界面展示 **GuiPiao**（与 PC 一致），勿另起品牌名或 slogan 盖过产品名 |
| 预览 | 开发期可用 MAUI Windows 目标 / Android 模拟器 / 真机；不以 WPF 内嵌预览代替 |

**一句话：** 手机是 GuiPiao 的触屏端，不是另一套 App。

## 2. 设计语言对齐（最高优先级）

### 2.1 真相源

| PC 资源 | 手机必须对齐的内容 |
|---------|-------------------|
| `Themes/LightTheme.xaml` / `DarkTheme.xaml` | **结构色** token 名与浅/深两套底色（窗体/面板/正文/边框等） |
| `ThemeManager` + `GeneralConfig` | **主题模式**与**强调色**：由用户在设置里选，运行时写入 `Accent*` token |
| `Resources/AppThemeTokens.xaml` | 字号阶梯语义 |
| `Icons/AppIcons.cs` | Segoe MDL2 字形与语义 |
| `Resources/AppControlStyles.xaml` | 主/次按钮层级、面板边框感 |

实现时：MAUI 使用**同名 token**；页面只绑定 token，**禁止**把某一款强调色 hex 写死进控件样式。票面预览等专用 `TicketVoucher*` 仍复用 PC 票面色。

### 2.2 颜色分两层（勿混为一谈）

#### A. 结构色（随浅/深主题字典，不随「强调色」设置）

用户选 **浅色 / 深色 / 跟随系统** 时切换整套底与字色。下表为 PC 主题字典中的结构色（手机须同名同值）：

**浅色**

| Token | 色值 | 用途 |
|-------|------|------|
| `WindowBackground` | `#FFFFFF` | 页底 |
| `ContentBackground` | `#F5F5F5` | 内容区浅底 |
| `PanelBackground` | `#F8F8F8` | 分区面板 |
| `TextPrimary` | `#212121` | 主文案 |
| `TextSecondary` | `#757575` | 次要说明 |
| `Border` | `#E0E0E0` | 描边 |
| `Divider` | `#EEEEEE` | 分割线 |
| `ControlBackground` | `#FFFFFF` | 输入框等 |
| `ImportFieldHighlight` | `#FFF3CD` | OCR 预填高亮（浅） |

**深色**

| Token | 色值 |
|-------|------|
| `WindowBackground` | `#2D2D30` |
| `ContentBackground` | `#252526` |
| `PanelBackground` | `#3E3E42` |
| `TextPrimary` | `#FFFFFF` |
| `TextSecondary` | `#E0E0E0` |
| `Border` | `#555555` |
| `ImportFieldHighlight` | `#5C4A1F` |

功能色 `Success` / `Warning` / `Error` / `Info` 与 PC 主题字典一致。  
票面预览复用 PC `TicketVoucher*`；深色主题下票面仍为浅色票底 + 黑字。

#### B. 强调色（用户在设置里决定）

与 PC **同一套设置模型**（`GeneralConfig` / `ThemeManager.ApplyAccentColor`）：

| `AccentColor` | 默认 hex（预设） |
|---------------|------------------|
| `MicrosoftBlue` | `#0078D4`（**出厂默认**，不是写死品牌色） |
| `FreshGreen` | `#28A745` |
| `VitalityOrange` | `#FD7E14` |
| `DarkPurple` | `#6F42C1` |
| `MinimalGray` | `#6C757D` |
| `Custom` | 用户自定义 hex（`CustomColor`） |

运行时由主题管理写入（名称与 PC 对齐）：

- `AccentBrush` / `PrimaryBrush`：填充（主按钮底、选中 chip、进度）  
- `AccentHoverBrush` / `AccentPressedBrush`：交互态  
- `AccentTextBrush`：主按钮上的字（一般为白）  
- `AccentForegroundBrush`：浅/深底上的强调字与描边（随当前主题模式由管理器推导，与 PC 一致）

**对齐含义：** 手机设置页提供相同选项与应用逻辑；UI 永远吃 token。  
**注意：** 主题/强调色属设置，**默认同隔离、不随行程同步**（与工程规范一致）；手机与 PC 可各自选择，互不覆盖。

文档或示例截图里出现的 `#0078D4`，仅表示「默认微软蓝」，验收时须能切换其它强调色且界面仍一致。

### 2.3 字体与字号

| 语义 | PC Token | 建议移动端 |
|------|----------|------------|
| 正文 | `BaseFontSize` 14 | 14–16（可读优先，比例保留） |
| 次要 | `SmallFontSize` 12 | 12–13 |
| 略大 | `LargeFontSize` 16 | 16–17 |
| 标题 | `TitleFontSize` 18 | 18–20 |

- 正文字体：系统 UI 无衬线（Windows Segoe UI / Android 默认无衬线），**不要**用展示衬线或「AI 落地页风」字体抢品牌。  
- 等宽仅用于配对码、倒计时等（PC 同步页 Consolas 语义 → 手机可用等宽或等宽数字）。

### 2.4 图标

- **唯一图标源：** Segoe MDL2 / Fluent 字形，语义对齐 `AppIcons`（`Sync` `Search` `Add` `Edit` `Link` `People` `Settings` `Camera` 等）。  
- **禁止**用 emoji 充当导航或主操作图标（PC 已全站替换 emoji）。  
- 底栏、顶栏、列表尾标与 PC 同一套字形语义，避免「手机一套、PC 一套」。

### 2.5 组件形态（像 GuiPiao，不像通用模板）

| 要 | 不要 |
|----|------|
| 细边框 + `PanelBackground` 分区（对齐设置页 Border 面板） | 厚阴影、大圆角「营销卡片墙」 |
| 主按钮实心 `Accent` + 白字；次按钮浅底/描边 | 全圆角胶囊按钮刷屏 |
| 状态 chip：选中用强调底或强调描边 | 彩虹标签条、渐变胶囊堆 |
| OCR 预填字段用 `ImportFieldHighlight` | 静默写库或无高亮直接入库 |
| 空态：一行说明 + 一个主操作 | 插画英雄区 + 多块促销 |

**圆角：** 可轻微（约 4px 语义，对齐 PC 部分 `CornerRadius="4"`），忌全面 `rounded-full`。  
**间距：** 面板内边距约 10–16；区块间距约 8–12，贴近设置页 `Margin/Padding` 节奏。

### 2.6 主题与强调色设置

- 手机「设置 → 外观」须提供与 PC 对等的能力：`ThemeMode`（浅/深/跟随）+ `AccentColor` 预设 + 自定义色；另可有字号档与删除确认（本机，不同步）。
- 应用逻辑对齐 `ThemeManager.ApplyTheme` / `ApplyAccentColor`：先套结构色字典，再覆盖强调色 token。  
- 设置存本机；**不要**做成「跟 PC 设置强制同步」或写死单一强调色。

### 2.7 反模式清单（出现即视为未对齐）

- 把某一 hex（含默认蓝）写死进控件，导致用户改强调色无效  
- 另做一套与 PC 预设不一致的强调色枚举  
- 紫粉渐变落地页、玻璃拟态、大面积霓虹描边（用户可选「暗夜紫」预设 ≠ 整站做成营销紫模板）  
- 奶油底 + 衬线大标题的模板风  
- 第一屏堆数据看板 / 多块互抢的营销模块  
- 与 PC 不同的产品名；emoji 当主图标；硬编码仅适浅色的字色/底色

### 2.8 对齐验收（PR / 自测必过）

1. 截图并排：PC 与手机在**同一主题模式**下，结构色与组件层级可一眼认为是同一产品。  
2. 在手机上切换至少两种强调色（含自定义），主按钮/选中态/强调字均跟随变化。  
3. 浅色 + 深色各走一遍主路径（列表 → 详情 → 表单 → 采集 → 同步）。  
4. OCR 预填高亮在深浅色下均可读；无 emoji 导航；无「改了设置颜色不变」的硬编码。

## 3. 信息架构（比「仅同步」完整）

```
底栏 Tab
├─ 行程     列表 / 搜索筛选 / 详情 / 新增编辑 · 标签管理
├─ 采集     拍照 · 相册 · 粘贴文本 → 预填表单
├─ 同步     连接/扫码/手输 · 配对 · 对齐 · 冲突（连接唯一枢纽）
└─ 设置     外观（主题/强调色/字号）· 删除确认 · 关于
```

### 3.1 做 / 不做

| 手机做 | 留给 PC |
|--------|---------|
| 行程 CRUD、状态、标签 | 票面布局工作台 |
| 采集（相机/相册/粘贴）+ 确认入库 | 完整仪表盘配置 |
| 简易票面只读预览 | 复杂地图大屏 |
| 同步中心与冲突处理 | 数据库备份/迁移/危险操作 |
| 年度轻量统计（可选，行程顶栏） | 导出 Excel/PDF 工作流 |
| 主题 / 字号 / 删除确认（本机设置） | |


原则与 PC 工程规范一致：**不伪造成熟**——未接通能力不做成「假可用」入口。

### 3.2 与 PC 共用的业务约束

- 写入行程：校验 → 确认 → 本地库；同步经 `sync_change`，**禁止 OCR 静默写库**。  
- 删除：软删语义与 PC 一致。  
- 设置/主题/票面布局：**不同步**（默认同隔离）。  
- PC 为权威；手机为副本 + 离线队列，回家/隧道对齐。

## 4. 关键界面说明（结构，非另套视觉）

下列结构用于实现对照；**视觉一律服从 §2**。

1. **行程列表：** 顶栏产品名 + 搜索 + 新增；状态 chip；行程用 Panel 行卡（车次、站、时刻、标签、状态）。  
2. **详情：** 简易票面只读 + 字段 + 编辑/改签/退票/删除（按钮层级同 PC）。  
3. **表单：** 字段与 PC 表单语义一致；OCR 来源字段高亮。  
4. **采集：** 拍照为主操作；相册/粘贴为次；说明「仅预填、需确认」。空白新增只在行程 Tab，采集不提供。  
5. **同步：** 连接唯一枢纽——扫码（相机为主、相册为辅，关掉 TabBar）；手输/检测/解除在连接子页（地址框可系统粘贴）；配对、对齐、冲突。  
6. **设置：** 外观（主题/强调色/字号）、删除确认、关于。标签归行程；连接归同步。不镜像 PC 十页设置树。

ASCII 线框可随实现迭代，**不得覆盖 §2 的强制对齐**。

## 5. 技术落点（实现时）

| 项 | 建议 |
|----|------|
| 工程 | 解决方案内 `GuiPiao.Mobile`（MAUI）；TFM 含 `net8.0-android`，并加 `net8.0-windows` 便于预览 |
| 协议 | 复用 `Model/Sync` 契约与 JSON snake_case；HTTP：`/v1/health` `/v1/pair` `/v1/changes` |
| 主题 | `Resources/Themes/Light.xaml` + `Dark.xaml`，token **同名同色** 对齐 PC |
| 图标 | 共享或镜像 `AppIcons` 常量，禁止分叉语义 |
| 本地库 | 手机侧 SQLite（结构与同步字段对齐）；对齐水位用 PC `seq` |
| 测试 | 协议/解析/入库单测优先；UI 整页慎测 |

推荐实施顺序：

1. 主题字典 + 空壳 Tab（先通过 §2.8 验收）  
2. 同步：配对 → pull/push  
3. 行程列表/详情/表单  
4. 采集  
5. 标签与轻量统计
