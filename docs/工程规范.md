> 本文是本仓库的**技术与协作总规范**。实现功能、改库、改 UI、加同步/OCR 前应先对照对应章节。  
> 专题细节可另见：`docs/TESTING.md`、`docs/功能规划-多端同步OCR与火车迷.md`、`docs/手机端MAUI设计规范.md`、车票预览相关文档。

## 1. 产品与仓库定位

| 项 | 约定 |
|----|------|
| 形态 | Windows 桌面端行程/车票管理工具（WPF） |
| 主工作台 | PC；手机为采集端（`GuiPiao.Mobile`），不以云库为主路径 |
| 解决方案 | `GuiPiao.sln` = 主工程 `GuiPiao` + 测试 `GuiPiao.Tests` + 手机 `GuiPiao.Mobile` |
| 语言/TFM | PC：C# / `net8.0-windows10.0.19041`；Mobile：MAUI `net10.0-windows`（预览）+ `net10.0-android`（`-p:BuildAndroid=true` 或已配置 SDK） |

**原则（产品侧）**

- 本地优先；写入 `train_ride_info` 须走与手填相同的表单/校验/Repository 路径。
- 不伪造成熟：未接通的能力不要在菜单里装作已可用。
- 改动保持最小必要范围；不顺手大重构、不擅自扩需求。

## 3. 目录与分层

```
GuiPiao/
  App.xaml(.cs)          启动、主题就绪、异常与恢复
  View/                  窗口与 UserControl（XAML + code-behind）
  ViewModel/             视图模型；复杂窗体用 partial / 子目录
  Model/                 实体与配置模型；同步契约在 Model/Sync/
  DataAccess/            Repository + Database 入口
  DataAccess/Schema/     版本化 schema 迁移（唯一改库结构入口）
  Services/              领域/基础设施服务（无 UI 或弱 UI）
  Utils/                 通用工具、配置管理
  Themes/                Light/Dark 主题资源字典
  Resources/             样式、转换器、地图静态资源、图片
  Controls/ Icons/ Converters/ Messages/
  Samples/               脱敏样例（如 OCR）；勿提交敏感原件
  docs/                  规划与规范
  GuiPiao.Tests/         全部自动化测试（主工程已 Compile Remove）
```

**依赖方向（推荐）**

```
View → ViewModel → Services / DataAccess → Model / Utils
```

- View 可保留布局与控件事件 code-behind；业务规则优先进 ViewModel / Services。
- DataAccess 不引用 View；Services 尽量不依赖具体 Window（弹窗经接口或 `ConfirmationService` 等现有封装）。

## 4. 配置与路径

| 类型 | 位置 | 说明 |
|------|------|------|
| 用户配置 JSON | `%AppData%\GuiPiao\Config\` | `JsonConfigManager`；清理 `bin` 不丢设置 |
| 旧版种子 | 程序目录 `Config\` | 仅首次拷贝缺失文件，**不覆盖**已有用户配置 |
| 数据库 | `databasesettings.json` 自定义路径，或搜索/`guipiao.db` | 连接串由 `ConfigManager` 提供 |
| 备份默认目录 | `%AppData%\GuiPiao\Backups\` | 见 `DatabaseBackupService` |
| 日志文件 | `{工作目录}\logs\app_yyyyMMdd.log` | 同时可写 SQLite `system_log` |

**约定**

- 新增设置页：JSON 文件名稳定、字段可缺省兼容；经对应 `*SettingsService` 读写。
- 禁止把密钥、证件号明文写进仓库内默认配置或 `Samples/`。
- 测试若需改库路径：仅用 `ConfigManager.OverrideDatabaseConnectionStringForTests`，用例结束清理临时库。

## 5. 数据库与 Schema 迁移（强制）

### 5.1 总则

- 运行时入口：`DataAccess/Database.Initialize()` → `SchemaMigrator.Apply` → `PRAGMA journal_mode=WAL`。
- 版本记录：SQLite **`PRAGMA user_version`**。
- **所有表结构变更**必须登记为 `DataAccess/Schema/SchemaCatalog` 中的有序迁移。
- **禁止**在 `Database.cs`、Repository、业务代码里散落长期 `EnsureColumn` / 无版本 `ALTER` 作为主路径。

### 5.2 如何新增迁移

1. 在 `SchemaCatalog.Migrations` **末尾**追加：  
   `new SchemaMigration(N, "snake_case_name", MigrateToN...)`  
   版本号必须从 1 连续递增（由 `SchemaMigrator` 校验）。
2. **禁止修改**已发布的 v1…v(N-1) 脚本内容（已安装用户可能已执行）。
3. v3 及以后：假定前序版本完整，优先直接 `ALTER` / `CREATE`；仅在兼容「半成品历史库」时才用 `SchemaSql.AddColumnIfMissing`。
4. 数据回填、索引、新表与该版本业务绑定，放在同一步事务内；一步失败整步回滚，`user_version` 不前进。
5. 在 `GuiPiao.Tests/DataAccess/` 补充空库升级与（如需要）旧库升级用例。

### 5.3 当前版本（摘要）

| Version | Name | 内容 |
|---------|------|------|
| 1 | `baseline_core` | 车站/行程/日志/标签等核心表 |
| 2 | `sync_foundation` | `sync_id`/`updated_at`/`deleted_at`、同步与配对相关表、存量回填 |

以 `SchemaCatalog` 与 `SchemaMigrator.CurrentVersion` 为准。

### 5.4 数据访问

- Repository 用 Dapper + 参数化 SQL；行程列表默认排除软删（`deleted_at` 为空）。
- 行程/标签的增删改若影响多端同步：同事务写入 `sync_change`（见 §8）。
- 危险操作（清空等）走既有 Dangerous/Maintenance 服务，并保留确认与备份意识。

### 5.5 多处 DDL 副本

`DatabaseMigrationService`、`IncrementalBackupService`、`DatabaseDangerousRepository` 等若含建表 SQL，**变更 schema 时必须同步评估**，避免「主库已升、旁路建库仍是旧结构」。长期目标是旁路也调用同一套迁移或共享最新 DDL 常量。

## 6. MVVM、消息与设置页

- 新 ViewModel：优先 CommunityToolkit 特性；复杂窗体可 `partial` 拆分文件。
- 跨模块通知：`Messages/*` + `WeakReferenceMessenger`，避免静态事件满天飞。
- 设置子页实现 `ISettingsViewModel`（未保存检测、保存、重新加载）；挂到 `SettingsWindow` 左侧导航。
- 弹窗/确认：复用现有 `ConfirmationService` / 统一 MessageBox 封装，避免各处 `MessageBox.Show` 风格不一致。

---

## 7. UI、主题与资源

- 主题：`ThemeManager` 切换 `Themes/LightTheme.xaml` / `DarkTheme.xaml`；强调色、字号、DPI 经现有 API。
- 控件样式、转换器：优先 `Resources/AppControlStyles.xaml`、`AppThemeTokens.xaml`、`AppConverters.xaml`；新色值用 `DynamicResource`，避免写死仅适浅色的颜色。
- `Resources/**` 非 XAML 内容由 csproj 复制到输出；**XAML 资源字典必须编译进程序集**，不要当 Content 拷贝。
- 地图：改 `Resources/Map/*` 后确认输出目录有最新文件。

## 8. 多端同步（无云）

详细产品决策见 `docs/功能规划-多端同步OCR与火车迷.md`。工程约束摘要：

| 项 | 约定 |
|----|------|
| 拓扑 | PC SQLite 为权威；手机离线队列，回家/隧道对齐 |
| 鉴权 | 配对码 → 长期 device token（只存哈希）；展示 TTL **60 秒**自动换码，兑换另有 **30 秒**上一窗容错（`SyncPairingService` 常量，UI 同源） |
| 变更 | `sync_change`：`change_id` 幂等，PC 单调 `seq` 为水位；历史行程需经 `SyncBaselinePublisher`（「开始配对」自动补发 /「发布现有行程」）写入后手机才能 pull |
| 实体 | `ride` / `tag` / `ride_tags`（见 `Model/Sync`） |
| 不同步 | 设置、票面布局、主题（默认同隔离） |
| 互备 | 同步成功即行程/标签双端副本；**灾难恢复以 PC 本地备份为准** |
| 删除 | 软删 + 变更日志；勿静默硬删已同步实体 |

**尚未完成的部分**（实现时按规划补齐，勿口头宣称已上线）：真机 Android 联调。
同步 HTTP：`SyncHttpServer`（`TcpListener`，默认端口 17880；默认尝试局域网 `IPAddress.Any`，失败回退本机；**不依赖 HTTP.sys urlacl**）+ `SyncApiDispatcher`（`/v1/health` `/v1/pair` `/v1/changes` `/v1/ocr` `/v1/stations` `/v1/conflicts` `/v1/conflicts/resolve`）；设置页可启停。手机端已接通配对、pull/push（含本地待推队列）、pull 入库、行程列表/详情/全字段表单、图片 OCR（经 PC CnOCR）、冲突箱、标签新建编辑、车站库全量同步、票面只读预览、列表状态筛选、「我的」年度轻量统计、扫码/剪贴板填服务地址。

写路径：`TrainRideRepository` / `TicketTagRepository` + `SyncChangeRepository` + `SyncPayloadSerializer`。  
Update 时必须先读库内 `sync_id`，禁止因 UI 未带 SyncId 而重新 `NewSyncId` 打断身份。

## 9. OCR / 导入

- 主路径：图/粘贴 → 文本 → 字段抽取 → **预填现有新增/编辑表单** → 人确认 → 同一保存路径。
- 禁止 OCR 专用静默写库。
- 引擎：`OcrRecognitionService` + 设置页环境（`OcrEnvironmentService`）；解析规则与语料见 `TicketTextExtractor`、`Samples/Ocr/`。
- 不维护「每种 App 截图像素模板」；按字段规则 + 来源族权重。
- `ServiceManager.TesseractService` 为历史占位，新功能不要接这条空实现。

## 10. 备份、恢复与日志

- 全量：`DatabaseBackupService`；增量：`IncrementalBackupService`（**不是**同步变更源）。
- 生命周期：`DatabaseLifecycleService`（启动/退出策略以数据库设置为准）。
- 同步前推荐触发全量备份；恢复备份后需意识到 sync 游标/`seq` 可能失效，应对齐策略（实现同步服务时写清）。
- 日志：`LogService` → 文件 + `system_log`；级别与清理在日志设置。业务关键路径用 `Info`/`Error`，避免仅靠 `Debug.WriteLine`。

## 11. 测试与完成标准

完整流程见 **`docs/TESTING.md`**。硬性要求：

1. 可测逻辑尽量不绑死 `Application.Current`、真实弹窗、固定用户路径。
2. 有行为变更则更新/新增 `GuiPiao.Tests` 用例；本地 `dotnet test` 通过后再算完成。
3. Schema / 同步 / 解析类优先单测；UI 整窗慎测。
4. 主工程不得编译进 `GuiPiao.Tests`（已由 csproj `Compile Remove` 保证，勿撤销）。

## 12. Git 与协作

- 仅在用户明确要求时提交；提交说明写清动机（why）。
- 不强制 push；不改 git config；不用破坏性命令除非明确要求。
- 不提交：用户库 `guipiao.db`、含证件的 OCR 原图、本地 `_build_check/` 产物、密钥。
- 文档：规范与已拍板决策写入 `docs/`；纯一次性讨论不必落盘。
